# The editing engine

Stapel edits documents with **sdkjs**, the JavaScript engine of Euro-Office (a fork of ONLYOFFICE).
It runs entirely in the browser; there is no Document Server. Only `packages/editor-core` talks to
it.

## Where it comes from

`engine/engine.json` pins one official Euro-Office Document Server release.
`bun run engine:prepare` (`engine/scripts/prepare.ts`, also run by `bun run dev`) downloads that
package, checks its SHA-256, and builds `engine/dist`, showing each step and the download's
progress:

| Path | What it is |
|---|---|
| `sdkjs/{common,word,cell,slide}` | the built engine, as shipped in the release |
| `sdkjs/common/AllFonts.js`, `fonts/` | the font index and web fonts, generated by the release's `allfontsgen` from its open-source fonts (`core-fonts`) |
| `sdkjs/slide/themes/` | the presentation themes (`themes.js` and one folder per theme), generated by the release's `allthemesgen` from the theme files it ships, as its install script does (`documentserver-generate-allfonts.sh`) |
| `vendor/xregexp/`, `vendor/jquery/` | globals sdkjs uses without loading them (jQuery: the text editor's page layout) |
| `x2t/` | the converter: ONLYOFFICE core's x2t compiled to WebAssembly ([cryptpad/onlyoffice-x2t-wasm](https://github.com/cryptpad/onlyoffice-x2t-wasm)), pinned in `engine.json` |
| `frame/x2t/worker.js` | the worker that runs x2t (from `engine/frame`) |
| `frame/editor/<editor>/main/index.html` | the pages that host the engine (from `engine/frame`) |
| `licenses/` | engine and font licenses |

`allfontsgen` is a Linux x86_64 binary, so preparing the engine needs Linux (CI does it and caches
the result by the hash of the spec, the scripts and the frame pages).

## How it is loaded

sdkjs resolves its own files relative to the page as `../../../../sdkjs/…` and `../../../../fonts/`
(`common/libfont/loader.js`, `common/GlobalLoaders.js`, `common/zlib/zlib.js`). The host page
therefore sits four folders below the engine root: `/engine/frame/editor/<editor>/main/index.html`,
with `word` for text documents, `cell` for spreadsheets and `slide` for presentations.

`mountEngineFrame` loads that page in a same-origin iframe and checks that the editor's API
constructor is there (`asc_docs_api` for text and presentations, `spreadsheet_api` for spreadsheets). The iframe keeps the engine's globals
(`Asc`, `AscCommon`, `AscFonts`, …) out of the app and gives each document its own engine.

The iframe has its own `Object`, `Array` and so on. sdkjs sometimes checks values with
`instanceof` (`CNumInfo.Parse` takes an object only if `value instanceof Object`), which fails for
objects made in the app's window. So everything handed to the engine is a primitive, JSON text, or
an object made with the frame's own constructors (`new win.Asc.asc_CColor(…)`).

## Why a converter

The engine opens and saves its own binary format ("DOCY", "XLSY", "PPTY"). Reading and writing
OOXML directly is an optional addon (`Asc.Addons.ooxml`, `CDocument.fromZip`) that is not part of
the Euro-Office build: setting the flag only moves the failure to `fromZip is not a function`.
So every open converts the .docx to the binary format with x2t, and every save converts back, as
CryptPad does. x2t runs in a worker (`createConverter`), so its large heap stays out of the page.

## How a document opens without a server

Opening is the same for every editor (`src/document.ts` `openDocument`); each editor adds its part
as an `EditorBinding`: the format, how its API is made, its state and events, its commands, what it
sets once the document is shown. `openWordDocument` (`src/word.ts`), `openSheetDocument`
(`src/cell.ts`) and `openPresentation` (`src/slide.ts`) are the bindings. The flow converts the
file (`docx → bin`, `xlsx → bin`, `pptx → bin`) and
then follows the mobile editors of web-apps (`apps/*editor/mobile/src/controller/Main.jsx`):

1. The editor's API inside the frame: `new Asc.asc_docs_api({"id-view": "editor_sdk"})`, or
   `new Asc.spreadsheet_api({"id-view": "editor_sdk", "id-input": "ce-cell-content"})`.
2. Register the callbacks (state events, `asc_onGetEditorPermissions`, `asc_onDocumentContentReady`,
   `asc_onError`).
3. `asc_setDocInfo(info)` with the URL `AscCommon.offlineMode`. That switches off the server
   connection: `_coAuthoringInit` keeps the co-authoring URL empty, `CDocsCoApi.init` then answers
   with a local "first connect" and an empty license instead of opening a socket
   (`common/apiBase.js`, `common/docscoapi.js`).
   In a shared session the URL is a blob URL of the converted document instead, and `window.io`
   in the frame is a socket.io stand-in that talks to the Stapel relay; see
   [collaboration](collaboration.md).
4. `asc_getEditorPermissions()`; the permissions callback calls `asc_LoadDocument()`.
5. In offline mode sdkjs asks for the file through `_openChartOrLocalDocument`, which would open an
   empty document. Stapel replaces it on the API instance with `asc_openDocumentFromBytes(binary)`.
6. `asc_onDocumentContentReady` → the editor is ready.

## How it saves

`asc_nativeGetFile()` (`word/api.js`) returns the document in the binary format as
`DOCY;v5;<size>;<base64>`; x2t converts it to .docx (`bin → docx`). The web app stores the result
on the server as a new version (`PUT /api/files/:id/content`, see [files](files.md)) and then calls
`markSaved(saved)`, which is `SetUnchangedDocument()`: "modified" turns false until the next change.
In a shared session it also tells the relay how much of the change log the stored copy holds; see
[collaboration](collaboration.md#saving).

## Commands and state

The UI never calls the engine. `editor-core` translates engine events into `EditorState`
(`src/events.ts`, `src/state.ts`) and offers commands (`src/commands.ts`):

| Command | Engine call | Event back |
|---|---|---|
| bold, italic, underline | `put_TextPrBold/Italic/Underline(value)` | `asc_onBold/Italic/Underline` |
| font size | `put_TextPrFontSize(size)` | `asc_onFontSize` |
| alignment | `put_PrAlign(AscCommon.align_*)` | `asc_onPrAlign` |
| undo, redo | `Undo()`, `Redo()` | `asc_onCanUndo`, `asc_onCanRedo` |
| strikethrough | `put_TextPrStrikeout(value)` | `asc_onStrikeout` |
| font | `put_TextPrFontName(name)` | `asc_onFontFamily`; the list: `asc_onInitEditorFonts` |
| text colour | `put_TextColor(asc_CColor)`, automatic: `Auto = true` | `asc_onTextColor` |
| paragraph style | `put_Style(name)` | `asc_onParaStyleName`; the list: `asc_onInitEditorStyles` |
| bulleted, numbered list | `put_ListTypeCustom(preset)`, end: `{ Type: "remove" }` | `asc_onFocusObject`, then `asc_GetCurrentNumberingId` / `asc_GetNumberingPr` |
| insert table | `put_Table(columns, rows)` | `asc_onFocusObject` with a `Table` object |
| rows, columns | `addRowAbove/Below()`, `addColumnLeft/Right()`, `remRow()`, `remColumn()`, `remTable()` | – |
| select all | `asc_EditSelectAll()` | – |
| superscript, subscript | `put_TextPrBaseline(AscCommon.vertalign_*)` | `asc_onVerticalAlign` |
| clear formatting | `ClearFormating()` | – |
| page break | `put_AddPageBreak()` | – |
| cut, copy, paste | `Cut()`, `Copy()`, `Paste()`; `false`: the browser refused | – |
| zoom | `zoomIn()`, `zoomOut()`, `zoom(percent)`, `zoomFitToWidth()`, `zoomFitToPage()` | `asc_onZoomChange(percent)`: `document.zoom` |
| mark saved | `SetUnchangedDocument()` | `asc_onDocumentModifiedChanged` |
| – | – | `asc_onCountPages` |
| – | – | `asc_onStartAction` / `asc_onEndAction` with `c_oAscAsyncAction.Disconnect`: `document.connected` |

## Comments

`src/comments.ts` reads and writes `asc_CCommentDataWord` (`word/api.js`) the way web-apps does
(`common/mobile/lib/controller/collaboration/Comments.jsx`). A comment carries two times: `Time`,
the local time written as if it were UTC, and `OOTime`, real milliseconds; Stapel keeps one time
in milliseconds and writes both.

| Command | Engine call | Event back |
|---|---|---|
| add (on the selection) | `asc_addComment(data)` | `asc_onAddComment(id, data)` |
| reply, resolve | `asc_changeComment(id, data)` with the whole comment and all replies | `asc_onChangeCommentData` |
| delete | `asc_removeComment(id)` | `asc_onRemoveComment` |
| go to | `asc_selectComment(id)` | – |
| – | `asc_showComments(false)` on content ready marks commented text | `asc_onShowComment(ids)`, `asc_onHideComment` |

On open, the engine reports every comment of the file with `asc_onAddComment`. Until there are
user accounts, comments are written as "Ich".

`asc_onDocumentModifiedChanged` carries no value (`word/api.js` `SetDocumentModified` sends it
bare); like web-apps (`documenteditor/mobile` `Main.jsx`), `editor-core` reads
`isDocumentModified()` when it arrives.

Style names are the engine's English ones (`Normal`, `Heading 1`), as stored in the .docx; the
toolbar shows the built-in ones in German (`apps/web/src/toolbar/style-labels.ts`). The list
presets are the first bullet and number presets of web-apps (`documenteditor/mobile`
`store/textSettings.js`), in `src/lists.ts`; the colour palette is Word's ten standard colours.

The spell checker is switched off (`asc_setSpellCheck(false)` on content ready): it needs the
Document Server's dictionary service, and without it every word is underlined.

The engine takes target values, not toggles, so a toggle command reads the current state first.

## Menus and the context menu

The editor's title row carries a menu bar as in a desktop office suite (`apps/web/src/ui/menu-bar.tsx`).
"Datei" and "Hilfe" are the same in every editor (`src/editor/file-menu.ts`); the editor adds its
own menus between them (`src/editor/word-menus.ts`), built from the state and the commands above.
The entries follow the desktop editors of web-apps (`documenteditor/main` `Toolbar.js`,
`DocumentHolder.js`); the shortcuts shown are the engine's own (`word/Editor/Shortcuts.js`).

A right click in the document makes the engine send `asc_onContextMenu` with a `CContextMenuData`
(`word/api.js` `sync_ContextMenuCallback`): the point relative to its view element and whether it
was in a header or footer. `editor-core` adds the view element's place in the frame
(`src/view.ts` `toContextMenuRequest`) and hands the request to `onContextMenu` listeners; the web
app adds the frame's place in the window and shows its own menu there, as web-apps does
(`DocumentHolder.js` `showPopupMenu`). Someone who may only look gets no context menu.

Cut, copy and paste from a menu go through the engine (`common/clipboard_base.js` `Button_Copy`,
`Button_Cut`, `Button_Paste`), which uses the async clipboard API; the frame allows it
(`allow="clipboard-read; clipboard-write"`). When the browser refuses, the entry answers `false`
and the app says which keys to use, like web-apps.

## Find and replace

`src/search.ts` fills a `CSearchSettings` (`common/api/searchSettings.js`: text, match case,
whole words) in the engine's frame and calls `asc_findText(settings, isNext)`,
`asc_replaceText(settings, replacement, isReplaceAll)` and `asc_endFindText()`, as web-apps does
(`documenteditor/main` `controller/Search.js`). The engine answers with
`asc_onSetSearchCurrent(current, total)` and, after replacing all, `asc_onReplaceAll(total,
replaced)`; both go into `state.search`. When nothing matches it sends nothing, so the command
reports that itself.

Strg+F and Strg+H are not handled by the engine (web-apps opens its own panel for them); a
keydown listener in the frame (`document.ts`, `onFindShortcut`) and one in the app window open
the search bar instead of the browser's search. Someone who may only look can search but not
replace.

## PDF and printing

This x2t build does not turn a document into a PDF by itself; it writes a PDF from the engine's
drawing commands, as the Document Server does for printing. `exportPdf` (`src/document.ts`) hands
the converter three things, the way CryptPad does (`www/common/outer/x2t.js`
`x2tConvertDataInternal`):

- the document in the engine's binary format (`asc_nativeGetFile()`), as `input.bin`;
- every page as drawing commands, as `pdf.bin` next to it: `WordControl.m_oDrawingDocument
  .ToRendererPart(true, true)`, what `word/api.js` `_downloadAs` sends for a PDF to print; x2t reads
  that file by this name (`X2tConverter/src/lib/pdf_image.h` `doct_bin2pdf`, CryptPad's patch);
- the fonts the document was drawn with, in `m_sFontDir`: the font files the engine has loaded
  (`AscCommon.g_font_loader`, status 0 or 1), fetched again from its font folder (the browser has
  them cached) and with the obfuscation of their first 32 bytes undone, as the engine does when it
  loads them (`common/Drawings/Externals.js`, `guidOdttf`); `src/print.ts`.

"Drucken" prints that PDF through the browser's dialog from a hidden frame (`apps/web/src/editor/pdf.ts`).
Strg+P is another key the engine leaves to its UI; it goes to the same place as Strg+F
(`onShortcut`). Images in the document are not in the PDF yet: the converter does not get the
document's media.

## Keyboard focus

The engine takes keys through a hidden text area in its frame (`common/text_input2.js`, id
`area_id`) and cancels `mousedown` on its canvas. A click into the page therefore does not move
focus out of the app: after a toolbar button had the focus, typing went nowhere. `editor-core`
listens for `pointerdown` in the frame and, when nothing in the frame holds the keys, focuses the
engine's input (`api.getFocusElement()`, `common/apiBase.js`); the engine's own `focus` handler
then turns its key events back on (`keepFocusOnClick` in `src/frame.ts`).

## Spreadsheets

`src/cell.ts` binds the spreadsheet engine (`cell/api.js`), following web-apps'
`spreadsheeteditor/mobile`:

- **Formula bar.** The engine types into an input it finds by id in its own document
  (`config["id-input"]`, `document.getElementById`), so the formula bar is part of the frame page
  (`engine/frame/editor/cell/main/index.html`), with the name box beside it. The name box shows
  `asc_onSelectionNameChanged` and jumps with `asc_findCell` on Enter.
- **German regional format.** `asc_setLocale(0x0407)` before loading: decimal comma, `;` between
  function arguments. Function names stay English (`SUM`), as the engine has no German names
  without a translation file.
- **State.** `asc_onSelectionChanged` brings the active cell (`asc_CCellInfo` →
  `CellXfs`: font, colours, alignment, wrap, number format; merge state), `asc_onSheetsChanged` and
  `asc_onActiveSheetChanged` the sheet tabs, read with `asc_getWorksheetsCount`,
  `asc_getWorksheetName`, `asc_isWorksheetHidden`, `asc_getActiveWorksheetIndex`.
- **The handler list.** The engine keeps one function per event as is and only several as a list.
  While opening it unregisters a callback of its own for `asc_onSelectionChanged`, which deletes
  the whole event when only one function is there (`cell/view/HandlerList.js` `remove`). An empty
  first callback keeps ours. It also calls only what its `asc_typeOf` calls "function", so callbacks
  are never `async` functions.

| Command | Engine call (cell/api.js) |
|---|---|
| bold, italic, underline, strikethrough | `asc_setCellBold/Italic/Underline/Strikeout(value)` |
| font, size | `asc_setCellFontName(name)`, `asc_setCellFontSize(size)` (at most 409) |
| text colour, fill | `asc_setCellTextColor(asc_CColor)`, `asc_setCellBackgroundColor(asc_CColor \| null)` |
| alignment, wrap | `asc_setCellAlign(AscCommon.align_*)`, `asc_setCellTextWrap(value)` |
| number format | `asc_setCellFormat(code)`: `General`, `#,##0.00`, `#,##0.00\ [$€-407]`, `0.00%`, `dd.mm.yyyy`, `@` |
| merge | `asc_mergeCells(c_oAscMergeOptions.Merge \| None)` |
| rows, columns | `asc_insertCells(c_oAscInsertOptions.InsertRows \| InsertColumns)`, `asc_deleteCells(…)` |
| undo, redo | `asc_Undo()`, `asc_Redo()`; state from `asc_onCanUndoChanged`, `asc_onCanRedoChanged` |
| sheets | `asc_showWorksheet(i)`, `asc_addWorksheet(name)`, `asc_renameWorksheet(name)`, `asc_deleteWorksheet()` |
| cut, copy, paste | `asc_Cut()`, `asc_Copy()`, `asc_Paste()` |
| zoom | `asc_setZoom(factor)`, `asc_getZoom()`; `asc_onZoomChanged(factor)` |
| find, replace | `asc_findText(asc_CFindOptions)` (the count), `asc_replaceText(options)`; `asc_onSetSearchCurrent`, `asc_onRenameCellTextEnd(found, replaced)` |
| PDF | `wb.calcPagesPrint()`, `wb.printSheets(pages, null).DocumentRenderer.Memory.GetData()`, as `cell/api.js` `_downloadAs` |

The menus and the context menu work as in the text editor (`apps/web/src/editor/sheet-menus.ts`).
The spreadsheet's right click hands over the mouse event itself (`WorkbookView.js` `onContextMenu`),
whose point is already in the frame's coordinates. Search follows web-apps
(`spreadsheeteditor/main` `controller/Search.js`): values in the active sheet, "whole words" as
"whole cell"; matches are marked with `asc_selectSearchingResults`, because the spreadsheet's
`asc_endFindText` fails in this build (it calls a `_cleanFindResults` that `WorkbookView.js` lacks).

The spreadsheet has no `SetUnchangedDocument`; its "modified" flag drops once the relay has the
changes (`asc_isDocumentModified`, `History.Have_Changes`).

## Presentations

`src/slide.ts` binds the presentation engine (`slide/api.js`), set up as web-apps'
`presentationeditor/mobile` does: `SetDrawingFreeze(true)` and `SetThemesPath` before loading,
`SetDrawingFreeze(false)`, `zoomFitToPage()` once the document is shown. The engine draws the slide
list and the notes field inside its frame. Its own texts (empty placeholders, "click to add
notes") come from the `translate` map the API is created with; `src/engine-texts.ts` has them in
German.

Character formatting is named and reported the same as in the text editor, so both share
`createCharacterCommands` and `textEvents` (`put_TextPrBold`, `asc_onBold`, …).

| Command | Engine call (slide/api.js) | Event back |
|---|---|---|
| new slide | `AddSlide(layoutIndex)` | `asc_onCountPages`, `asc_onCurrentPage` |
| layout | `ChangeLayout(layoutIndex)`; the layouts with their pictures: `asc_onUpdateLayout` (`CLayoutThumbnail`) | – |
| duplicate, delete | `DublicateSlide()` (the engine's spelling), `DeleteSlide()` | `asc_onCountPages` |
| bullets, numbering | `put_ListType(0 \| 1, 1)`, end: `put_ListType(…, -1)` (`CommonController.js` `fFillBullet`) | `asc_onListType` |
| character formatting, alignment, undo | as in the text editor | as in the text editor |
| clipboard, zoom, find and replace | as in the text editor (`Copy`, `zoom`, `asc_findText`, …) | as in the text editor |
| PDF | `WordControl.m_oDrawingDocument.ToRendererPart(true, false)`: all slides, as `slide/api.js` `_downloadAs` | – |

A right click sends `CContextMenuData` as in the text editor; its type tells the slide
(`c_oAscContextMenuTypes.Main`) from the slide list (`Thumbnails`), and the context menu offers the
slides first in the list (`apps/web/src/editor/slide-menus.ts`).

New presentations come from `packages/ooxml` (`pptx.ts`): one master with the layouts
"Titelfolie", "Titel und Inhalt", "Nur Titel" and "Leer", a theme with Office's default colours
and Calibri, 16:9.
